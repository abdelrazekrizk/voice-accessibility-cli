# Voice Accessibility CLI: setup

## Requirements

- Python 3.10 or later.
- An ElevenLabs API key and network access for real audio generation.
- A local media player if you want to listen to generated MP3 files.

Audio is generated by the remote ElevenLabs service. Requests can consume account quota or incur charges, and access to particular voices/models depends on the account. Review the current terms and limits for your own ElevenLabs account before sending text.

## Install

Run from the `voice-accessibility-cli` project root in PowerShell:

```powershell
if (-not (Test-Path .\.venv\Scripts\python.exe)) { python -m venv .venv }
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Open `.env` and set `ELEVENLABS_API_KEY` to your own key. The application loads it through `python-dotenv`. Keep `.env` private: it is ignored by Git, and API keys should never be pasted into issues, logs, or commits. The other placeholders in `.env.example` are not needed by this project.

This project does not use `BACKBOARD_API_KEY`. Backboard comparison is an optional feature of the sibling event-schema-validator project, not a dependency of voice generation.

## Run the CLI

From the project root, display available commands:

```powershell
& .\.venv\Scripts\python.exe src\cli.py --help
```

Generate and save speech:

```powershell
& .\.venv\Scripts\python.exe src\cli.py generate --text "Doorbell rang at the front door" --output doorbell.mp3
```

A relative `--output` path is placed under the project `audio_output/` directory. An absolute path is used as supplied. If `--output` is omitted, the current implementation does not save or play the returned audio; it only reports that generation completed.

Create a composed smart-home alert:

```powershell
& .\.venv\Scripts\python.exe src\cli.py event --event-type motion --location "Back door" --urgency high --output motion.mp3
```

List the built-in voice names:

```powershell
& .\.venv\Scripts\python.exe src\cli.py list-voices
```

This command currently reports a built-in list, not voices available in the account.

## Batch input

The CLI accepts a JSON array of strings or an object with a `texts` array. Per-item voice/rate metadata is not supported.

```json
{
  "texts": [
    "Doorbell at the front door",
    "Motion detected near the garage"
  ]
}
```

```powershell
& .\.venv\Scripts\python.exe src\cli.py batch --input-file .\texts.json --output-dir .\audio_output\batch
```

The command writes numbered MP3 files into the selected output directory and prints the success/failure totals. Batch synthesis sends requests to ElevenLabs just like single-item generation.

## Tests

Run the complete test suite:

```powershell
& .\.venv\Scripts\python.exe -m pytest tests/ -v
```

The tests replace the ElevenLabs SDK calls with mocks; they need no API key and do not make live requests. To run an actual API request, use the CLI or Python example in [Usage](USAGE.md), understand that it may consume quota, and ensure the selected account permits the requested voice/model.

## Troubleshooting

- **Missing API key:** check that `.env` exists in the project root and contains `ELEVENLABS_API_KEY=...`; restart the command after editing it.
- **HTTP 402 / `paid_plan_required`:** the requested primary voice/model may not be available to the account. The code retries only this specific restriction with the configured fallback voice/model; other API errors are raised as a `RuntimeError`.
- **File not where expected:** relative single-output paths go under `audio_output/`; batch output paths are resolved from the current working directory.
- **Voice/rate settings seem unchanged:** the CLI currently records these settings but does not pass them as synthesis settings to the SDK. See the limitations in [Usage](USAGE.md).
